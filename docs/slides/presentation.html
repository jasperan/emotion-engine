Emotion Engine

Multi-Agent Simulation System

Where AI agents develop emotional intelligence through disaster

Why simulate emotion?

Most AI benchmarks test logic. But cooperation, trust, and moral reasoning under stress? Those don't fit in a multiple-choice test.
  • Emergent behavior only appears when agents have personality, memory, and real stakes
  • Reproducible research needs deterministic, seedable simulations (not vibes)
  • LLM decision-making under pressure is still poorly understood

What Emotion Engine does

A local-first simulation engine that drops LLM-powered agents into disaster scenarios. Each agent has a unique personality, tracks relationships, remembers events, and cooperates (or doesn't) based on who they are.

  • 10 diverse personas navigate a rising flood, from an ER doctor to a scared 8-year-old
  • Every decision traced through a cognitive pipeline: think, plan, act, reflect
  • Real-time monitoring via terminal TUI or web dashboard
  • Cross-run analytics for comparing behaviors across seeds and scenarios

How a tick works

Each simulation step runs through 4 phases. The world evolves, agents react, then everything gets persisted.

Phase 1
Environment agents generate world events
→
Phase 2
Human agents process (parallel by scene)
→
Phase 3
Reaction round for intra-step responses
→
Persist
Snapshot, WebSocket emit, consensus check

The agent system

Four distinct agent types, each with different responsibilities. Human agents are the stars; the rest form the supporting cast.

👤

Human Agent

LLM-driven with persona, Big Five traits, stress, health, inventory, relationships

🌊

Environment Agent

Controls hazards, locations, items, and world events. Sets the stage.

🎬

Designer Agent

Guides the scenario narrative. Keeps things moving when agents stall.

📋

Evaluator Agent

Post-run analysis. Scores cooperation, identifies narrative arcs and key moments.

Cognitive pipeline

Every human agent runs this pipeline each tick. Context in, reasoned action out.

Build Context
world state + messages
→
Think
internal reasoning
→
Plan
set goals + steps
→
Act
execute JSON action
→
Reflect
update memory
  • System prompt encodes persona, Big Five traits, current goals
  • LLM responds in JSON mode; fallback to natural language parsing if malformed
  • Intent memory persists goals across ticks; stagnation detection forces new plans

What makes each agent unique

Immutable Persona

  • Demographics age, background, occupation
  • Big Five traits openness, conscientiousness, extraversion, agreeableness, neuroticism (1-10)
  • Skills what they're capable of

Mutable State (per tick)

  • Health + Stress affects decision quality
  • Location physical position in the world
  • Inventory tools, supplies, resources
  • Relationships trust per agent pair

Communication protocol

Agents talk through a structured message bus with three channel types.

Direct

One-to-one. Private conversations between two agents. Used for negotiation, requests, warnings.

Room-scoped

Everyone at the same location hears it. Announcements, group discussions, calls for help.

Broadcast

World-wide. Environment events, designer guidance, emergency alerts.

  • Multi-turn conversations with explicit initiation and turn-taking
  • 10-round safety limit prevents infinite loops
  • Communication frequency modulated by personality traits

LLM infrastructure

An abstraction layer routes inference calls to the best available provider. vLLM for throughput, Ollama as a fallback.

↓ per-agent-type model routing
vLLM :8010
Primary. Continuous batching.
Parallel inference. JSON mode.
Ollama :11434
Fallback. Single-slot.
Semaphore-gated. Sequential.
  • Default model: Qwen/Qwen3.5-4B (auto-disables thinking tokens)
  • Automatic fallback chain: vLLM -> Ollama -> fallback model
  • Token budget per agent: 50,000 streamed characters per run

Getting started

Two paths: Docker (one command) or manual setup.

# Docker: one-command install
curl -fsSL https://raw.githubusercontent.com/jasperan/
    emotion-engine/main/install.sh | bash

# Or manual: backend
cd backend
pip install -e .
emotionsim run --scenario "Rising Flood" \
    --max-steps 50 --seed 42
# TUI dashboard
cd tui
make build
./emotionsim-tui            # auto-starts backend + vLLM
./emotionsim-tui --no-backend --no-vllm  # existing services

Knowledge graph layer

The mirofish-integration branch bolts on a knowledge graph powered by Oracle SQL/PGQ. Agents remember by relevance, not recency.

Graph Memory

Hybrid search: 0.7 vector cosine + 0.3 BM25. A bridge memory from 30 steps ago surfaces when an agent reaches a bridge.

Document Ingestion

Text in, NER/RE extraction, graph entities out. Auto-generates scenarios from uploaded documents.

Persona Generator

Graph entities become Big Five + MBTI personas. Characters generated from the source material.

Report Agent

Post-sim analysis with InsightForge deep search and PanoramaSearch breadth scanning.

Opinion dynamics + social systems

Agents don't just talk; they influence each other. Opinions shift based on trust, personality bias, and who's talking.

  • Opinion vectors per topic (-1.0 to 1.0). "Evacuation: 0.8" means strongly in favor.
  • Shift formula: direction * influence * trust * (1-bias) * speed. Max +-0.3 per interaction.
  • Sentiment tracking detects tipping points: when a group suddenly converges or diverges on a topic.
  • Influence network maps who influenced whom. Identifies super-spreaders and opinion anchors.

Scaling to 100+ agents

Not every agent needs an LLM call. Lightweight agents use personality-driven rules for decisions: zero GPU cost.

Rule-based decisions

  • Action weights from Big Five traits
  • Extraversion -> speak
  • Agreeableness -> help
  • Openness -> explore/move

Dynamic promotion

  • Background agents promoted when addressed directly
  • High-extraversion agents in active scenes
  • Leaders with low stress step forward
